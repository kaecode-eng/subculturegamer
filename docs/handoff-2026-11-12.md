## 3. 작업 원칙 (기존 + 이번 작업에서 추가)

- 블로그 공개·상태 변경은 **사용자 승인 후**에만.
- h2 섹션 사이에 구분자와 공백(SEP 규칙). 블록으로는 공백 + 구분선 + 공백.
- 한국어 글은 마지막에 **humanize-korean**으로 윤문. 결과 끝의 `<!-- HUMANIZE-SUMMARY … -->` 블록은 반드시 지우고 저장한다.
- 저장 후 **객체 캐시 + LiteSpeed 캐시 + Cloudflare 캐시**를 비운다. Cloudflare는 관리 막대의 LiteSpeed 메뉴 → **"모두 제거 - Cloudflare"** 로 비웠다(WP Cloudflare Super Page Cache 메뉴는 관리 화면에 보이지 않았다). 비운 뒤 로그아웃 상태에서 확인한다.
- WordPress에서 확인한 동작:
  - 글 편집 화면에서 올린 이미지는 **글의 작성 날짜 폴더**에, 미디어 메뉴에서 올리면 현재 월 폴더에 저장된다. 같은 이름이 있으면 `-1`, `-3`이 붙는다. 같은 이름으로 다시 올려도 옛 주소는 살아나지 않으니 **글 속 이미지는 편집기에서 직접 교체**한다.
  - 따옴표에 붙은 마크다운 굵게(`**“…”**`)는 붙여 넣을 때 변환되지 않는다. 툴바나 블록 HTML을 쓴다.
  - 본문 교체는 **코드 편집기에 블록 HTML**을 붙여 넣는 방식이 가장 안정적이었다.
  - 이미지 가림 처리는 일반 블러가 아니라 **사전 블러 + 큰 블록 모자이크**로 해야 글자가 복원되지 않는다.
- 비공개 글 검토는 미리보기 화면을 **PDF로 인쇄**해 전달하는 방식이 안전했다.

## 4. 환경·도구 메모

- **WordPress 쓰기 작업**: REST 응용 프로그램 비밀번호 인증은 여전히 401(`rest_not_logged_in`)이다. 서버는 LiteSpeed(Vertex cPanel) + 앞단 Cloudflare이고, `.htaccess` 맨 아래에 다음을 넣었지만 해결되지 않았다.
  ```
  SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
  RewriteEngine On
  RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
  ```
  11/15 개편 적용은 **Claude 데스크톱 앱의 내장 브라우저에 관리자로 로그인한 세션(쿠키 + `rest-nonce`)** 으로 했다. 대량 작업은 이 방식을 쓰고, 인증을 고치려면 WP 관리자 → 도구 → 사이트 상태의 Authorization 헤더 경고부터 확인한다.
- **공개 글 가져오기**: [tools/import_posts_rest.py](../tools/import_posts_rest.py) (요구: Python, `pip install markdownify`, `curl`). 11/15 세션의 로컬 환경에는 Python이 없어서 공개 REST 본문을 같은 형식으로 직접 변환해 저장했다.
- **통계**: [planning/traffic/README.md](../planning/traffic/README.md), `node tools/blog-stats.mjs --days 28`. 인증 파일은 Windows `AppData\Local\SubcultureGamerStats`에만 둔다.
