## 1. 이번 작업에서 끝낸 일

워드프레스 기본 댓글 UI를 네이버 블로그·티스토리·브런치에 익숙한 형태로 바꾸고 글 좋아요를 더했다. 코드는 mu-plugin 파일 하나다: [wordpress/sg-comments.php](../wordpress/sg-comments.php).

| 영역 | 결과 |
|---|---|
| 댓글 폼 | 한 박스형 입력창, 글자 수, `등록` 버튼. 로그인 시 아바타+닉네임. 비회원은 닉네임·이메일 **선택 입력**(비우면 익명) |
| 댓글 목록 | 제목 "댓글 N", 상대 시간, "답글달기", `@멘션`, 작성자 뱃지 |
| ⋮ 메뉴 | 방문자: 링크 복사·신고 / 관리자: 링크 복사·수정·삭제 |
| 신고 | 첫 신고 시 관리자 메일, 3건이면 자동 숨김, 관리자 댓글 목록 🚩 열과 "신고 기록 지우기" |
| 좋아요 | ♡ 좋아요 / 💬 댓글 N 버튼, 관리자 글 목록 ♥ 열(정렬)·대시보드 TOP 10, GA4 `post_like`/`post_unlike` |
| 캐시 | 등록 직후 `?sg_new` 캐시 우회, 승인 대기 시 `?sg_pending` 안내, 댓글 변화 시 해당 글만 Cloudflare 캐시 삭제 |

버전별 변경과 PR 링크는 README의 「버전 이력」에 있다.

### 실사이트에서 확인한 것 (2026-11-17)
- 적용 버전 **1.5.0**. 폼·하트·⋮ 메뉴(비로그인) 표시, 스크립트 오류 0건.
- 익명·이메일 없는 댓글이 바로 공개됨. 등록 직후 일반 주소에서도 보임(Cloudflare `MISS`).
- 관리자 댓글 목록 아래 "Cloudflare 캐시 삭제(댓글): 성공". 휴지통 이동 후에도 일반 주소에서 즉시 사라짐.
- 신고 메일 수신, 관리자 ♥ 열 정렬, GA4 실시간 수신(시크릿 창)은 사용자가 확인.
- 시험 댓글(#481~#484)은 모두 휴지통으로 정리했다. #480은 실제 독자 댓글이라 유지.

## 2. 현재 사이트 설정 (바꾸면 동작이 달라지는 것)

| 위치 | 현재 값 | 영향 |
|---|---|---|
| 설정 → 토론 | 이름·이메일 필수 **해제** | 폼의 닉네임·이메일이 선택 입력. 다시 체크하면 코드 수정 없이 필수로 바뀐다 |
| 설정 → 토론 | 수동 승인 **해제**, 이전 승인 필요 **해제** | 댓글 바로 공개. "이전 승인 필요"를 켜면 이메일 없는 익명 댓글은 항상 대기가 된다 |
| 설정 → 토론 | 새 댓글 메일 알림 **켜짐**, 링크 2개 이상 대기 **유지** | 사후 관리용 |
| LiteSpeed Cache → CDN → Cloudflare | Cloudflare API **켜짐**(키·영역 저장) | 댓글 변화 시 Cloudflare 캐시 삭제가 이 값을 쓴다. 끄면 다른 방문자에게 최대 10분 옛 페이지가 보인다 |
| GA4 맞춤 정의 | 측정기준 `title` = 이벤트 매개변수 `post_title` | 2026-11-16 이후 이벤트만 글별로 나뉜다 |
| Site Kit | 로그인 사용자는 GA 집계 제외로 보임 | 본인 브라우저에서는 이벤트가 안 잡힌다. 확인은 시크릿 창에서 |

## 4. 작업 원칙 (이번 작업에서 정한 것)

- **배포는 사용자가 cPanel에서 파일을 덮어쓴다.** 순서: PR 병합 → `main`의 `wordpress/sg-comments.php` 업로드 → 화면이 바뀌는 변경이면 Cloudflare·LiteSpeed 캐시 비우기 → 세션이 바깥에서 확인.
- **버전 번호**: 파일 상단 `Version`을 올리고 README 「버전 이력」에 PR과 함께 적는다.
- **검증**: 실제 글 HTML을 내려받아 새 CSS·JS를 넣고 Playwright로 확인한다(모의 AJAX, 서버 상태를 바꾸는 요청은 `abort`). PHP는 WordPress 함수를 흉내 낸 스텁으로 분기를 확인한다. 실제 WordPress에서는 돌려 보지 못하므로 PR에 "배포 후 확인 필요" 항목을 남긴다.
- **실사이트 확인 시 상태를 바꾸지 않는다.** 하트·신고·삭제는 누르지 않거나 요청을 막는다. 신고는 실제 메일이 가므로 사용자가 시크릿 창에서 한다.
- **캐시 확인 방법**: 일반 주소와 `?x=난수` 주소를 비교하고 `Cf-Cache-Status`, `Age`, `X-Litespeed-Cache` 헤더를 본다. 업로드 직후 일반 주소에 옛 화면이 보이면 Cloudflare 캐시 문제다.
- **인라인 JS 주의**: 여러 기능이 한 `DOMContentLoaded` 함수 안에 있다. 새 변수 이름이 기존 함수 이름(`u`, `post` 등)을 덮지 않게 한다(1.4.2에서 실제로 발생, 1.4.3에서 수정).
