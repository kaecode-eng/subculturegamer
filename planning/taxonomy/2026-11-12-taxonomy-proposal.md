### 1-2. 주요 문제 7가지

1. **작품 태그를 "언급"만으로 붙이고 있습니다.** `mentions.json` 기준으로 블루 아카이브 태그가 붙은 28편 가운데 본문에서 블루 아카이브를 5회 이상 언급한 글은 2편(시나리오 포스트모템 44회, 아이템 컨셉 6회)뿐입니다. 태그 아카이브가 "이 작품을 다룬 글 모음" 역할을 하지 못하고, 앞으로 붕괴: 스타레일·창세기전 템페스트 허브를 태그와 연동할 때 노이즈가 됩니다.
2. **뜻이 겹치는 태그(동의어)가 있습니다.**
   - 내러티브 디자인 / 로어 디자인: 21편에 동시 부착
   - K-Console Conference / 콘솔게임 개발자 컨퍼런스: 같은 행사의 영문·한글 표기
   - GAME DAYS 2026 / K-Console / 콘솔게임 개발자 컨퍼런스 / GIGDC 2026: 한 글에 같은 행사를 묶는 태그가 4개
   - 미장센 / (연출 관련 글 전반): 미장센 태그가 연출 글 일부에만 붙어 있습니다
3. **표기가 공식명과 다릅니다.** `붕괴 3rd`의 공식 한국어 표기는 `붕괴3rd`(공백 없음), `붕괴 스타레일`의 공식 표기는 `붕괴: 스타레일`(콜론 포함)이고, 포스트 제목은 이미 공식 표기를 씁니다. 란스X는 제목에 `[란스 10]`, `Rance X -결전-`, 태그에 `란스X`가 섞여 있습니다.
4. **태그가 아닌 것이 태그로 들어가 있습니다.** 개발자 인명 4개(코다카 카즈타카, 타이난 실베스터, 파벨 사스코, 하라다 카츠히로), 연도가 붙은 행사명 3개, 0편 태그 3개입니다.
5. **카테고리 경계가 흐립니다.**
   - 서브컬처 담론 3편(서브컬처의 정의, 타투, 섹슈얼 콘텐츠)이 「분석」에 들어가 있는데, 실제로는 게임 분석이 아닙니다.
   - 행사·업계 동향 글이 리뷰(지스타, 아니메재팬, GAME DAYS, 콜라보 카페)와 기획 노트(GDC 2026, NDC 2026, 2024 게임산업)로 흩어져 있습니다. CLAUDE.md의 "서브컬처(정의·트렌드·콜라보)" 영역을 받아줄 카테고리가 없습니다.
   - 「기타」의 정의는 "게임·서브컬처 외"인데, 란스X 설치·한글화 가이드 2편이 기타에 들어가 있습니다.
6. **시리즈 성격의 분류가 섞여 있습니다.** 「나니노벨」 카테고리는 사실상 한 연재(45편)입니다. 독자 의도(Unity VN 엔진 튜토리얼)가 뚜렷하고 인덱싱되는 카테고리라서 유지하는 편이 맞습니다. `창작` 태그는 초단편 스토리 연재(5편), `퀘스트 디자인`·`게임 모션`은 연재와 주제를 겸합니다.
7. **나니노벨 글의 태그가 들쭉날쭉합니다.** 45편 중 17편에만 `비주얼 노벨`이 붙어 있어 기준이 보이지 않습니다.

### 1-3. 잘 되어 있는 점 (유지할 것)

- **카테고리 베이스가 제거되어 있습니다**(`/gamedesign/`, `/category/gamedesign/`는 `/gamedesign/`으로 301). 카테고리 슬러그가 곧 루트 URL이므로 슬러그를 유지하는 것이 가장 중요합니다.
- SEO 플러그인은 **SEOPress**입니다(Yoast·RankMath 아님). 카테고리 아카이브는 `index`이고 메타 설명이 작성되어 있습니다. **태그 아카이브는 이미 `noindex, follow`**이며 사이트맵(`sitemaps.xml`)에는 post·page·category만 들어 있습니다. 그래서 태그 개편의 SEO 위험은 낮습니다.
- Redirection 플러그인이 활성 상태입니다(`redirection/v1` 네임스페이스 확인).
- 시리즈 허브(`/quest-design-series/`, `/gamers-brain-series/`, `/honkai3rd-return-system-reverse-design/`)는 고정 페이지가 아니라 **포스트**로 발행되어 있습니다.

## 2. 새 구조 제안

### 2-1. 설계 원칙

- **카테고리 = 독자가 무엇을 얻으러 왔는가(콘텐츠 유형).** 포스트당 1개만 붙이고, 고정 목록으로 운영하며 거의 늘리지 않습니다.
- **태그 = 무엇에 관한 글인가(패싯).** 통제 어휘에서만 고르고, 새 태그는 승인 절차를 거칩니다.
- **시리즈 = 허브 포스트 + 본문 시리즈 내비게이션.** 카테고리로 만들지 않고, 필요할 때만 태그를 보조로 씁니다.
- 기존 카테고리 슬러그 7개는 **모두 유지**합니다. 이름만 다듬고 새 카테고리 1개를 추가합니다.

### 2-4. 이름 짓기 규칙

1. **공식 한국어 표기를 그대로 씁니다**(띄어쓰기·기호 포함). 붕괴3rd, 붕괴: 스타레일, 블루 아카이브. 국내 정발명이 없으면 국내 통용 표기를 쓰고(란스X), 태그 설명에 원제(Rance X -결전-)를 적습니다.
2. **slug는 영문 kebab-case**로 씁니다. 한글·퍼센트 인코딩 slug는 금지합니다. 기존 slug에 트래픽이나 외부 링크가 있으면 이름만 바꾸고 slug는 유지합니다.
3. 복수형·연도·버전·인명은 넣지 않습니다(`GDC 2026` ✕ → `GDC` ○).
4. **동의어는 금지합니다.** 하나를 대표어로 정하고 나머지는 태그 설명에 "포함 개념"으로 적습니다. 예: 연출(미장센·카메라 워크·시네마토그래피 포함), 설정 기획(로어 디자인·세계관 포함), 포스트모템(회고 포함)
5. **카테고리와 같은 이름의 태그는 금지합니다**(예: `리뷰`, `게임 분석`, `나니노벨` 태그 금지).
6. 모든 태그에 **1~2문장 설명**을 씁니다. SEOPress 메타 설명과 태그 아카이브 상단에 같이 쓰입니다.

### 2-5. 부착 규칙

- 포스트당 태그는 **0~5개**(권장 1~3개)입니다. 패싯마다 최대 2개입니다.
- 태그 0개는 「기타」 글과, 통제 어휘에 맞는 태그가 없는 글(예: 서브컬처의 정의)에만 허용합니다. **억지 태그는 붙이지 않습니다.**
- 작품 태그는 "본문 비중 테스트"를 통과해야 합니다. 예시로 1~2회 언급하는 정도라면 붙이지 않고 본문 링크로 처리합니다.

## 4. WordPress 이전 계획

> 아래는 실행 절차 제안입니다. **현재 사이트에는 아무 변경도 하지 않았습니다.**

### 4-1. 준비

1. 전체 백업(DB 포함)을 만들고, REST API 스냅샷(`raw/`)을 비교 기준으로 보관합니다.
2. Google Search Console에서 최근 6개월 카테고리·태그 URL 노출 기록을 내보냅니다. 태그는 noindex라서 거의 없을 것으로 예상합니다. 클릭이 있는 태그 URL은 slug를 유지하는 쪽으로 판단을 조정합니다.

### 4-2. 카테고리 (URL에 영향 있는 부분부터, 위험도 낮은 순서)

3. 신규 카테고리 `subculture-trends`를 만들고, SEOPress에서 제목·메타 설명을 작성합니다. 만들기 직전에 같은 slug의 포스트·페이지가 없는지 다시 확인합니다.
4. 13편의 카테고리를 옮깁니다. 포스트 URL은 그대로라서 리다이렉트가 필요 없습니다.
5. 기존 카테고리 3개의 **이름만** 바꿉니다(기획 노트 → 게임 기획, 분석 → 게임 분석, 나니노벨 → 나니노벨 가이드). slug는 건드리지 않습니다. SEOPress의 카테고리 제목 템플릿, 메뉴 라벨, 빵부스러기, 사이드바 위젯 문구를 같이 갱신합니다. 「기타」 설명도 수정합니다.

### 4-3. 태그

6. 새 태그 23개를 slug와 설명까지 갖춰 미리 만듭니다.
7. 이름만 바꾸는 태그(붕괴3rd, 붕괴: 스타레일, 설정 기획): 편집 화면에서 이름만 수정합니다.
8. slug를 바꾸는 태그(생성형 AI, 초단편 스토리, GAME DAYS): slug를 수정한 직후 Redirection에 `옛 URL → 새 URL` 301을 등록합니다. 퍼센트 인코딩 URL은 인코딩된 형태와 디코딩된 형태를 둘 다 등록합니다.
9. CSV의 `제안_태그` 열대로 포스트별 태그를 다시 부착합니다. 「글 → 일괄 편집」은 태그 추가만 되고 제거가 안 되므로, 제거가 많은 작품 태그(블루 아카이브, 란스X 등)는 태그 아카이브 화면에서 글을 하나씩 열어 빼거나, 관리자 권한으로 WP-CLI(`wp post term set`)를 쓰는 편이 빠릅니다.
10. 병합(미장센 → 연출, K-Console·콘솔게임 개발자 컨퍼런스 → GAME DAYS)을 진행합니다. 대상 글에 새 태그를 붙인 다음 옛 태그를 삭제하고 301을 등록합니다.
11. 삭제할 태그 10개를 지우고 301을 등록합니다(3-2 표의 목적지 참고). 존재하지 않는 태그 URL을 404로 두지 않습니다.

### 4-4. SEO 주의사항 (SEOPress 기준)

- **태그 아카이브 noindex는 유지**합니다(현재 설정이 맞습니다). 41개 중 30편 이상인 태그는 유니티 하나뿐이라 대부분 얇은 아카이브입니다. 나중에 작품 태그(붕괴: 스타레일 등)를 색인하고 싶어지면 해당 태그 아카이브에 설명문 300자 이상과 대표 글 링크를 넣은 다음, 태그별로 index를 켜는 방식으로 접근합니다. 다만 그 역할은 허브 포스트가 맡는 편이 낫습니다.
- 카테고리 아카이브는 index를 유지하고, 신규 카테고리에도 메타 설명을 반드시 씁니다.
- 카테고리 베이스가 제거된 구조이므로, 앞으로 카테고리 slug를 바꾸면 **루트 URL이 바뀝니다.** 카테고리 slug는 바꾸지 않는다는 원칙을 문서화합니다.
- Redirection에서 301 등록 후 `curl -I`로 상태 코드를 확인하고, 404 로그를 2주 동안 지켜봅니다.
- 사이트맵은 SEOPress가 자동으로 갱신하므로, 갱신된 `category-sitemap1.xml`을 Search Console에 다시 제출합니다.
- `성인 게임` 태그는 noindex라 검색 노출은 없지만, AdSense가 켜져 있는 사이트이므로 태그 아카이브 페이지에서 광고가 표시되는 방식은 한 번 점검합니다.
