# WordPress 커스텀 코드

subculturegamer.com(Neve FSE 테마)에 직접 올리는 코드 모음.

## sg-comments.php — 한국형 댓글 UI + 글 좋아요

워드프레스 기본 댓글 UI를 네이버 블로그·티스토리·브런치에 익숙한 형태로 바꾸고, 글 좋아요(하트)를 더한 mu-plugin.

### 현재 상태 (2026-11-17)

| 항목 | 상태 |
|---|---|
| 사이트 적용 버전 | **1.5.0** (`wp-content/mu-plugins/sg-comments.php`) |
| 설정 → 토론 | 이름·이메일 필수 **해제**, 수동 승인 **해제**, 이전 승인 필요 **해제**, 새 댓글 메일 알림 **켜짐** |
| LiteSpeed Cache → CDN → Cloudflare | Cloudflare API **켜짐**(키·영역 저장됨). 댓글 변화 시 캐시 삭제가 이 값을 쓴다 |
| GA4 | `post_like`/`post_unlike` 수신 확인, 맞춤 측정기준 `title`(`post_title`) 등록 |
| 실사이트 확인 | 폼·하트·⋮ 메뉴(비로그인) 화면, 익명 댓글 바로 공개, 등록 직후 일반 주소 반영(Cloudflare `MISS`), 댓글 목록 아래 "Cloudflare 캐시 삭제: 성공" |

배포는 **cPanel에서 파일 덮어쓰기**로 한다. 이 저장소의 클라우드 세션은 WordPress REST 인증이 `401`이라 직접 올릴 수 없다(사이트에 Code Snippets는 설치돼 있어 인증만 해결되면 스니펫 방식으로 옮길 수 있다. 옮길 때는 mu-plugins 파일을 먼저 지워야 함수 중복 오류가 나지 않는다).

### 알아둘 점

- 개발 중 검증은 실제 글 HTML에 코드를 넣은 Playwright 미리보기와 WordPress 함수를 흉내 낸 PHP로 했다. 관리자 화면 기능(♥ 열 정렬, 신고 기록 지우기 등)은 배포 후 사람이 확인했다.
- 화면(폼·목록·버튼)이 바뀌는 업데이트는 업로드 후 **Cloudflare 캐시 비우기**가 필요하다. 관리자 화면·서버 동작만 바뀌면 필요 없다.
- 시험 댓글·신고는 실제 메일 알림과 공개가 일어나므로 시크릿 창에서 하고, 끝나면 ⋮ → 삭제로 정리한다.
- 브런치의 ⋮ 메뉴 중 비회원 본인 댓글 수정·삭제(비밀번호 방식)는 넣지 않았다. 댓글 양에 비해 작업이 커서 보류.

### 설치·업데이트

1. GitHub main의 `wordpress/sg-comments.php`를 받아 cPanel 파일 관리자에서 `wp-content/mu-plugins/sg-comments.php`로 업로드(폴더가 없으면 생성). 활성화 절차 없이 바로 적용된다.
   - 또는 Code Snippets/WPCode에 첫 줄 `<?php`를 뺀 나머지를 PHP 스니펫으로 붙여넣는다. 두 방법을 동시에 쓰면 함수 중복으로 사이트가 멈추니 하나만 쓴다.
2. LiteSpeed 캐시 전체 비우기 → Cloudflare 캐시 비우기.
3. 글 하나를 열어 하트 클릭 → 새로고침 후에도 숫자가 유지되는지 확인.

### 좋아요 숫자의 기준

| 어디서 보나 | 정확도 | 용도 |
|---|---|---|
| 관리자 **글 → 모든 글**의 ♥ 열, **대시보드 TOP 10** 위젯 | 정확(광고 차단기 영향 없음) | **공식 숫자.** 글별 누적 좋아요 |
| GA4 `post_like` / `post_unlike` 이벤트 | 차단기 사용자만큼 적게 잡힘 | 조회수 대비 비율, 유입 경로별 반응 같은 **경향 분석** |

- 두 숫자가 다른 게 정상이다. 개수는 관리자 화면, 비율·경향은 GA로 본다.
- 같은 IP(회사·같은 와이파이)는 1명으로 센다. 원본 IP는 저장하지 않는다(해시만 저장).
- 데이터 위치: 글 메타 `_sg_likes`(개수), `_sg_like_keys`(중복 방지용 해시).

### 비회원 댓글: 닉네임·이메일 선택 (1.4.2)

- **설정 → 토론 → "댓글 작성자는 이름과 이메일을 입력해야 합니다"**를 따른다. 현재 해제 상태라 둘 다 선택 입력이다.
  - 해제: `닉네임 (선택 · 비우면 익명)`, `이메일 (선택 · 공개되지 않음)`
  - 체크: 두 칸 모두 필수로 바뀐다(코드 수정 불필요).
- 닉네임을 비우면 WordPress가 **익명**으로 표시한다. 답글 멘션도 `@익명`으로 나온다.
- 댓글 등록 직후에는 돌아가는 주소에 `?sg_new=댓글ID`를 붙여 Cloudflare 캐시(최대 10분)를 건너뛴다. 작성자는 자기 댓글을 바로 보고, 주소창의 쿼리는 화면이 뜬 뒤 지워진다. 다른 방문자에게도 바로 보이도록 아래 Cloudflare 캐시 삭제가 함께 동작한다(1.5.0).
- 승인 대기(또는 스팸 판정) 댓글은 등록 직후 폼 위에 "댓글이 등록됐습니다. 운영자 확인 후 공개됩니다." 안내를 띄운다(`?sg_pending=1`, 1.4.3). WordPress 기본 안내는 작성자 이메일이 있어야만 나오기 때문.

### 댓글 변화 시 Cloudflare 캐시 삭제 (1.5.0)

LiteSpeed Cache의 Cloudflare 연동은 **"모두 비우기" 때만** Cloudflare를 비운다. 그래서 댓글이 달려도 Cloudflare가 저장한 글 페이지(최대 10분)가 그대로 나갔다.

- 댓글이 **공개**될 때, 공개 댓글이 **수정·삭제·스팸·숨김(신고 3건)**될 때, 숨긴 댓글을 다시 **승인**할 때 그 **글 주소 하나만** Cloudflare에서 지운다. 승인 대기 댓글은 화면에 안 나오므로 지우지 않는다.
- Cloudflare 접속 정보는 **LiteSpeed Cache → CDN → Cloudflare**에 저장된 값(API 키/토큰, 영역, 이메일)을 그대로 쓴다. 그곳의 "Cloudflare API"가 꺼져 있으면 동작하지 않는다.
  - 글로벌 API 키(37자리)+이메일이면 `X-Auth-Key` 방식, 그 밖에는 API 토큰(`Bearer`) 방식으로 보낸다.
- 방문자에게 응답을 보낸 뒤 요청하므로 댓글 등록 속도에는 영향이 없다.
- 마지막 결과는 관리자 **댓글** 목록 맨 아래에 "Cloudflare 캐시 삭제(댓글): 성공/실패 · 시각"으로 표시된다. 실패하면 LiteSpeed의 Cloudflare 키 권한(Zone → Cache Purge)을 확인한다.

### 댓글 운영 방식: 바로 공개 + 사후 관리

티스토리·네이버 블로그처럼 댓글은 바로 공개하고, 문제 댓글은 나중에 지운다.

설정 → 토론:
- "댓글은 수동으로 승인해야 함" **해제**
- "이전에 승인된 댓글이 있어야 함" **해제** (켜져 있으면 이메일 없는 익명 댓글은 항상 대기가 된다)
- 이메일 알림 "누군가 댓글을 쓸 때마다" **체크**
- 댓글 검토 "링크 2개 이상이면 대기"는 유지 (링크 많은 댓글은 대부분 광고)

거르는 장치: Akismet(스팸 자동 분류) → 독자 신고(3건이면 자동 숨김, 첫 신고 시 메일) → 관리자 ⋮ → 삭제. 가끔 댓글 → 스팸을 열어 잘못 걸린 댓글은 "스팸 아님"으로 돌린다.

### 댓글 ⋮ 메뉴 (1.4.0~)

| 누가 | 메뉴 |
|---|---|
| 모든 방문자 | 링크 복사, 신고 |
| 관리자(로그인) | 링크 복사, 수정(관리자 편집 화면), 삭제(휴지통으로 이동) |

- 신고: 같은 IP는 댓글당 1회, 1시간에 10건까지. 첫 신고 때 관리자 이메일로 알림이 간다.
- **신고 3건**(`SG_REPORT_HIDE_AT`)이 쌓이면 댓글이 자동으로 **승인 대기**로 바뀌어 숨겨진다. 관리자 **댓글** 목록의 🚩 신고 열에서 확인하고, 문제없으면 다시 **승인**한다. 관리자가 승인하면 신고 기록도 함께 지워진다.
- 신고 기록만 지우려면: 관리자 **댓글** 목록에서 그 댓글에 마우스를 올리면 나오는 **신고 기록 지우기**를 누른다(신고가 있는 댓글에만 보인다).
- 관리자 메뉴는 HTML에 넣지 않고 로그인한 관리자에게만 브라우저에서 추가한다. 페이지 캐시에 섞이지 않는다.

### GA4 설정 — 완료 (2026-11-16)

| 항목 | 상태 |
|---|---|
| 이벤트 전송 `post_like` / `post_unlike` | 완료. 시크릿 창에서 실시간 보고서 수신 확인 |
| 맞춤 측정기준 | 완료. 표시 이름 `title`, 범위 이벤트, 매개변수 `post_title` (관리 → 데이터 표시 → 맞춤 정의) |
| `post_id` 측정기준 | 미등록(선택). 글 제목을 자주 바꾸게 되면 같은 방식으로 추가 |

- `post_title` 측정기준은 2026-11-16 이후 수집된 이벤트에만 적용된다. 그 전 이벤트는 글별로 나뉘지 않는다.
- 측정기준 표시 이름(`title`)은 ⋮ → 수정으로 바꿀 수 있다. 매개변수와 범위는 만든 뒤 바꿀 수 없다.

**보는 곳**

- 바로 확인: 보고서 → **실시간 개요** → "이벤트 이름별 이벤트 수" 카드(최근 30분)
- 누적: 보고서 → 참여도 → **이벤트**에서 `post_like`. 일반 보고서는 하루 이상 지난 데이터만 보이고 반영까지 24~48시간 걸린다
- 글별 분석: 탐색 → 자유 형식. 행 `title`, 열 `이벤트 이름`, 값 `이벤트 수`, 필터 이벤트 이름 = `post_like`·`page_view` → 글별 좋아요율 = post_like ÷ page_view

**본인 방문이 안 잡힐 때**

WordPress에 로그인한 브라우저나 광고 차단 확장이 켜진 브라우저에서는 `page_view`를 포함해 아무 이벤트도 GA에 기록되지 않는다(Site Kit 로그인 사용자 제외 설정 또는 차단기). 고장이 아니다. 동작 확인은 **시크릿 창**에서 한다.

### GA 누락 줄이기: Cloudflare Google tag gateway (선택)

GA 스크립트를 자기 도메인 경로로 불러와 차단기 누락을 줄인다. 좋아요뿐 아니라 조회수·유입 경로 데이터 전체에 적용된다. 강한 차단기(uBlock Origin 등)는 여전히 일부 막는다.

1. Cloudflare 대시보드 → `subculturegamer.com` 존 → **Google tag gateway** 페이지(Engagement 메뉴 쪽)
   - 계정 권한이 Super Administrator / Administrator / Zaraz Admin(도메인 범위 사용자는 Domain Administrator)이어야 한다.
2. **Turn on and configure Google tag gateway** 켜기
3. Google 태그 ID 입력: 현재 사이트 태그는 `GT-PBSCH8B`(Site Kit이 삽입). GA4 관리 → 데이터 스트림 → 태그 설정에서 확인 가능.
4. 측정 경로 입력: 사이트에서 쓰지 않는 경로로 지정(예: `/sgm/`). 기존 글·페이지 슬러그와 겹치면 안 된다.
5. 확인: 글을 열고 브라우저 개발자 도구 → Network에서 GA 요청이 `subculturegamer.com/<측정 경로>/...`로 나가는지, GA4 실시간 보고서에 방문이 잡히는지 확인.

주의: 설정은 존 전체(모든 서브도메인)에 적용된다. Google Tag Manager/Google 태그 관리 화면(관리 → Google tag gateway)에서 Cloudflare 계정을 연결해 켜는 방법도 있다.
