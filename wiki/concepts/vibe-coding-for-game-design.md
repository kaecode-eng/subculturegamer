## 개념 설명

게임 기획자가 자연어로 작은 프로그램이나 프로토타입을 만들고, 직접 실행하며 요구사항과 구조를 검증하는 방식이다. 코드를 제품에 바로 투입하는 것이 아니라 기획자가 평소 정의하던 입력·출력·조건·상태·예외를 작동하는 형태로 옮겨 보는 데 초점이 있다.

프로토타입은 기획서를 대체하지 않는다. 화면 흐름과 인터랙션은 프로토타입이 빠르게 보여주고, 상세 규칙·예외·데이터 구조·정책·변경 이력은 문서가 남긴다.

## 블로그에서 다룬 맥락

- HTML 프로토타입은 여러 장의 설명보다 버튼을 직접 눌러 보는 방식으로 기획 의도를 빠르게 전달했다.
- 대사 태그 누락 검사기, 퀘스트 플래그 검색기, 퀘스트 흐름 시각화 도구처럼 반복적이고 실수하기 쉬운 업무를 작은 도구로 분리할 수 있다.
- 노드 기반 퀘스트 기획 도구를 만들면서 시각화가 복잡성을 없애는 것이 아니라, 문서 안에 숨은 복잡성을 더 일찍 드러낼 수 있음을 확인했다.
- 실행되는 AI 생성 코드를 제품 코드로 오해하지 않는다. 보안 정책, 성능, 유지보수, 확장성, 인수인계 가능성을 검토하고 어디까지 직접 만들고 어디서 협업할지 정한다.

## 미개척 각도

- 게임 기획자가 처음 만들기 좋은 검사기·시각화 도구 사례
- 프로토타입에서 발견한 문제를 제작용 기획서에 되돌리는 방법
- 개인용 바이브 코딩 도구를 팀 공용 도구로 전환할 때 필요한 문서화와 인수인계 기준
- 퀘스트 노드 도구의 최소 기능과 데이터 교환 형식 비교
